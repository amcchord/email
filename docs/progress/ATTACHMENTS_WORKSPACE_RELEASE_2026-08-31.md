# First-class Attachments Workspace Release — 2026-08-31

## Outcome

The mail client now has a first-class, read-only Attachments workspace over
already synchronized local metadata. Users can discover files for one exact
connected account, search filename/sender/subject, filter by type and sent or
received direction, navigate with the keyboard, explicitly preview or download
safe content, and open the exact parent message. Ordinary browsing performs no
provider read, attachment-cache write, mail mutation, calendar mutation, or AI
call.

Application/runtime commit and production evidence are recorded after the
authorized deployment below.

## Durable data and API contract

- Additive Alembic revision `b1c2d3e4f5a6`, directly from
  `a0b1c2d3e4f5`, adds only `ix_attachments_email_id`; no row or content
  backfill is required.
- `POST /api/attachments/query` is browser-session authenticated, POST-only,
  `private, no-store`, and requires one exact active owned `account_id`.
  Missing, inactive, and foreign accounts share 404 and never fall back.
- The bounded request accepts a 256-character literal query, a type filter,
  sent/received direction, a 1–50 page size, and a signed cursor bound to the
  exact user/account/query/filter tuple.
- Stable keyset order is message date descending with email and attachment IDs
  as deterministic ties. Draft, Spam, Trash, and inline parts are excluded.
- The response allowlist contains only account/attachment/email IDs, sanitized
  filename and content type, nullable byte size/date/sender/subject, and sent
  direction. Provider IDs, cache/storage paths, content IDs, recipients, Bcc,
  snippets, bodies, and AI output never leave the service.
- Listing is PostgreSQL-only. Existing exact email-and-attachment Preview and
  Download endpoints remain the only byte paths and run only after an explicit
  user action.

## User experience

- Attachments is the second item in **More**, after Contacts. It is lazy-loaded,
  available in the command palette, and has the `G X` navigation chord.
- Exact-account selection, literal search, type and direction filters, loading,
  empty, retry, pagination, and stale-session/account handling are responsive
  and accessible.
- `J`/`K` move selection, Enter explicitly previews, `D` downloads, `O` opens
  the exact parent message, `/` focuses search, and Escape closes preview while
  restoring focus to the originating row.
- Parent navigation is a one-shot session-only handoff into Inbox. It carries
  the exact account and email identity, waits for Inbox authority, and is
  mutually exclusive with the existing Contacts handoff.
- At 390x844, the workspace has no document or internal horizontal overflow;
  the preview becomes a full-screen surface and all primary controls remain
  reachable.

## Safety review and generated acceptance

- Three independent data, safety, and UX audits were completed before freeze.
  The bounded P0/P1 review found no P0 issue and four P1 issues: an old-account
  result could survive a programmatic account fallback, row Enter could
  intercept a nested action button, one malformed sender could fail a complete
  page, and generated byte-size fixtures could drift from their headers. Each
  was fixed with a focused regression.
- Browser QA then found one additional release blocker: CSS-grid min-content
  sizing could create an internal horizontal scrollbar at 390px. The row and
  list constraints were corrected and exact client/scroll widths now match.
- The loopback `.example.test` fixture covers two users, two accounts, safe and
  hostile-looking metadata, pagination, search/filtering, stale sessions,
  transient failures, explicit preview/download counters, and parent handoff.
  It never connects to Gmail, Calendar, AI, or another host.
- Generated desktop and 390x844 acceptance verified anchored More placement,
  exact-account replacement, inert hostile filenames, query-free URLs,
  keyboard/focus behavior, explicit preview, and zero implicit byte reads.
  Final counters were four metadata queries, two explicit generated preview
  reads, zero downloads, zero provider reads/writes, zero mail/calendar
  mutations, zero unexpected writes, and zero external network calls.

## Rollback boundary

The migration contains only a conventional foreign-key lookup index. The
application can be rolled back independently. The index can be downgraded
without losing attachment rows or content, although normal recovery should
keep the index and roll application code forward. A protected pre-b1 backup is
still taken as the production migration boundary.

## Follow-on boundary

Thumbnails, OCR, AI summaries, bulk ZIP, compose reuse, provider-wide
reindexing, durable file organization, and writable actions are deliberately
outside this release. Each would change the byte, privacy, or mutation model
and requires a separately reviewed milestone.
